# Reference: Rollout Booby-Trap Catalog

> Forensic case studies of catastrophic production rollout failures across the software industry and their architectural preventions.

## 1. The Knight Capital Flag Recycling Catastrophe (2012)

- **The Incident:** On August 1, 2012, Knight Capital Group suffered a \$440 million loss in 45 minutes, leading to the firm's collapse.
- **Root Cause Mechanics:** An engineer repurposed a defunct, 8-year-old feature flag (`Power Peg`) to activate a new automated trading algorithm. During deployment across 8 production servers, an technician failed to copy the new binary to the 8th server. When the flag was enabled in configuration, the 8th server executed the legacy `Power Peg` code—which had been repurposed without removing its original logic—entering an infinite loop buying high and selling low into the market.
- **Architectural Prevention:**
  - **Permanent Identifier Tombstoning:** Once a feature flag is deprecated, its identifier is permanently blacklisted. Automated linters reject any PR attempting to declare an existing or previously registered flag name.
  - **Complete Branch Demolition:** Code guarded by graduated feature flags must be ripped out within 14 days; dormant code paths must never remain in binaries.

## 2. The Rolling Fleet Deserialization Cascade

- **The Incident:** During a canary deployment of a high-throughput recommendation service, error rates jumped to $100\%$ across both $N$ and $N+1$ nodes, causing a complete fleet brownout.
- **Root Cause Mechanics:** Pod $N+1$ serialized an updated Protobuf response containing a newly added enum variant. Pod $N$ (still running legacy code) received the response via an internal gRPC service call. The legacy deserializer was configured with strict enum validation, throwing an unhandled `IllegalArgumentException` on the unknown ordinal. The unhandled exception crashed worker threads, causing Kubernetes to restart pods in a vicious cascading crash loop.
- **Architectural Prevention:**
  - **Tolerant Reader Invariant:** Serializers and deserializers must treat unknown fields and unmapped enums as non-fatal fallback variants.
  - **Bidirectional Matrix Verification:** CI pipelines must execute integration tests where version $N$ parses payloads generated by version $N+1$, and vice versa.

## 3. The Unfenced Shadow Billing Nightmare

- **The Incident:** A fintech startup attempted a "safe shadow launch" of a new checkout billing pipeline by mirroring 5% of incoming live checkout POST requests to the new service in the background.
- **Root Cause Mechanics:** While the new service read from a synthetic shadow database, the payment processor client SDK was initialized with production API keys. The shadow workers executed real API calls to Stripe, resulting in thousands of customers being charged twice for a single shopping session.
- **Architectural Prevention:**
  - **Zero-Trust Side-Effect Fencing:** Shadow environments must run in network namespaces with hard firewall blocks on external payment endpoints.
  - **Dummy Payment Sinks:** Payment clients in shadow mode must inject in-memory no-op drivers that return synthetic success tokens without egressing network packets.

## 4. The Undead Flag Combinatorial Outage

- **The Incident:** An e-commerce platform experienced an intermittent lock contention deadlock on its primary database cluster that only manifested on Friday evenings.
- **Root Cause Mechanics:** The codebase accumulated over 120 unmaintained feature flags over three years. Under high traffic, a newly introduced caching flag coincided with an obscure, undocumented promotional flag from two years earlier that had never been deleted. The combination of both active flags caused an unexpected non-atomic transaction rollback loop.
- **Architectural Prevention:**
  - **Strict 90-Day Expiration (TTL):** Every feature flag must have a hard `expires_at` date. Any flag older than 90 days fails automated CI builds until a demolition PR is merged.
  - **Flag Count Quotas:** Services are limited to a maximum of 10 concurrently active feature flags. New flags cannot be created until obsolete flags are decommissioned.

## 5. The Sunday Night Big-Bang Disaster

- **The Incident:** An engineering team spent 18 months rewriting an authentication monolith into a microservice. At 2:00 AM on Sunday, DNS records were switched 100% to the new service. By 8:30 AM Monday, login failures surged to 40% globally, blocking millions of mobile users.
- **Root Cause Mechanics:** Subtle differences in URL percent-encoding handling and session cookie domains caused older iOS clients to drop session credentials. Because the database had been altered destructively during the cutover, rolling back required 16 hours of data restoration.
- **Architectural Prevention:**
  - **The Strangler Fig Protocol:** Monoliths must be dismantled slice by slice behind a reverse proxy facade with real-time traffic shifting.
  - **Canary Ramping:** Traffic must ramp gradually ($1\% \rightarrow 5\% \rightarrow 25\% \dots$) with sub-second automated rollbacks on any SLO breach.
